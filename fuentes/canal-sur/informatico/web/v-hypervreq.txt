# Requisitos del sistema para Hyper-V en Windows y Windows Server

- Se aplica a: ✅ Windows Server 2025, ✅ Windows Server 2022, ✅ Windows Server 2019, ✅ Windows Server 2016, ✅ Windows 11, ✅ Windows 10, ✅ Azure Local 2311.2 and later

## 

Hyper-V tiene requisitos de hardware específicos y algunas características de Hyper-V tienen otros requisitos. Use los detalles de este artículo para decidir qué requisitos debe cumplir el sistema para poder usar Hyper-V de la forma planeada.

A continuación, revise el catálogo de Windows Server. Tenga en cuenta que los requisitos de Hyper-V superan los requisitos mínimos generales para Windows Server, ya que los entornos de virtualización requieren más recursos informáticos.

Si ya usa Hyper-V, es probable que pueda usar el hardware existente. Los requisitos generales de hardware han cambiado mínimamente de Windows Server 2012 R2, pero necesita hardware más reciente para usar máquinas virtuales blindadas o asignaciones de dispositivos discretas. Estas características dependen de la compatibilidad específica con hardware, como se describe más adelante en este artículo. Además, la principal diferencia en el hardware es que la traducción de direcciones de segundo nivel (SLAT) ahora es obligatoria, no recomendada.

Para obtener más información sobre el número máximo de configuraciones de Hyper-V admitidas, como el número de máquinas virtuales en ejecución, consulte Planificación de la escalabilidad de Hyper-V en Windows Server. La lista de sistemas operativos que puede ejecutar en una máquina virtual se trata en Sistemas operativos invitados con Windows compatibles con Hyper-V en Windows Server.

## Requisitos del sistema operativo

Hyper-V se puede habilitar en estas versiones de Windows:

- Windows 10 Professional o Enterprise

- Windows 11 Professional o Enterprise

## Requisitos generales

Independientemente de las características de Hyper-V que quiera usar, necesitará:

- 
Un procesador de 64 bits con traducción de direcciones de segundo nivel (SLAT) Para instalar los componentes de virtualización de Hyper-V, como el hipervisor de Windows, el procesador debe tener SLAT. Sin embargo, no es necesario instalar herramientas de administración de Hyper-V como Conexión de máquina virtual (VMConnect), Administrador de Hyper-V y cmdlets de Hyper-V para Windows PowerShell. Consulte Comprobación de los requisitos de Hyper-V a continuación para averiguar si el procesador tiene SLAT.

- 
Extensiones del modo monitor de máquina virtual.

- 
Suficiente memoria. Planee al menos 4 GB de RAM. Cuanta más memoria, mejor. Necesitará suficiente memoria para el host y todas las máquinas virtuales que quiera ejecutar a la vez.

- 
La compatibilidad con la virtualización está activada en el BIOS o UEFI:

- 
Virtualización asistida por hardware. Esto está disponible en procesadores que incluyen una opción de virtualización: específicamente procesadores con tecnología de virtualización Intel (Intel VT) o amd Virtualization (AMD-V) tecnología.

- 
La prevención de ejecución de datos (DEP) mediante hardware tiene que estar disponible y habilitada. En los sistemas Intel, es el bit XD (bit para deshabilitar la ejecución). En los sistemas AMD, es el bit NX (bit de no ejecución).

## Comprobación de los requisitos de Hyper-V

Abra Windows PowerShell o una ventana de símbolo del sistema y escriba:

`Systeminfo.exe
`

Desplácese hasta la sección Requisitos de Hyper-V para examinar el informe. Si todos los requisitos de Hyper-V enumerados tienen un valor sí, el sistema puede ejecutar el rol de Hyper-V. Si algún elemento devuelve No, compruebe los requisitos enumerados en este documento y realice ajustes siempre que sea posible.

## Requisitos para características concretas

En esta sección se enumeran los requisitos para la asignación discreta de dispositivos y las máquinas virtuales blindadas.

### Asignación de dispositivos discreta

 Los requisitos del host son similares a los requisitos existentes para la característica SR-IOV en Hyper-V.

- 
El procesador debe tener la tabla de páginas extendidas (EPT) de Intel o la tabla de páginas anidadas (NPT) de AMD.

- 
El conjunto de chips debe tener:

- 
Reasignación de interrupciones: VT-d de Intel con la funcionalidad de reasignación de interrupciones (VT-d2) o cualquier versión de la unidad de administración de memoria de E/S de AMD (MMU de E/S).

- 
Reasignación de DMA: VT-d de Intel con invalidaciones en cola o cualquier MMU de E/S de AMD.

- 
Servicios de control de acceso (ACS) en puertos raíz PCI Express.

- 
Las tablas de firmware deben exponer la MMU de E/S al hipervisor de Windows. Esta característica puede desactivarse en UEFI o BIOS. Para obtener las instrucciones necesarias para hacerlo, consulte la documentación del hardware o póngase en contacto con el fabricante del hardware.

 Los dispositivos necesitan GPU o memoria rápida no volátil (NVMe). En el caso de la GPU, no todos los dispositivos admiten la asignación discreta de dispositivos, solo algunos de ellos. Para comprobarlo, consulte la documentación del hardware o póngase en contacto con el fabricante del hardware. Para obtener más información sobre esta característica, incluido cómo usarlo y consideraciones, consulte Discrete Device Assignment--Description (Asignación de dispositivos discretos): descripción y antecedentes en el blog virtualización.

### Máquinas virtuales blindadas

Estas máquinas virtuales dependen de la seguridad basada en la virtualización y están disponibles a partir de Windows Server 2016.

 Los requisitos del host son:

- 
UEFI 2.3.1c. Admite el arranque seguro y medido.

Los dos requisitos siguientes son opcionales para la seguridad basada en virtualización en general, pero es necesario para el host si desea que la protección que proporcionen estas características:

- TPM v2.0. Protege los recursos de seguridad de la plataforma.

- IOMMU (Intel VT-D). Permite al hipervisor proporcionar protección de acceso directo a memoria (DMA).

 Estos son los requisitos de la máquina virtual:

- Generación 2.

- Windows Server 2012 o posterior como sistema operativo invitado.

## Comprobación final

Si se cumplen todos los requisitos de sistema operativo, hardware y compatibilidad, verá Hyper-V en el Panel de control: Activar o desactivar las características de Windows y tiene dos opciones:

- plataforma de Hyper-V

- Herramientas de gestión Hyper-V

Note

Si ve la Plataforma de hipervisor de Windows en lugar de Hyper-V en el Panel de control: activar o >desactivar las características de Windows, es posible que el sistema no sea compatible con Hyper-V. Compruebe los requisitos anteriores.
Si ejecuta systeminfo en un host existente de Hyper-V, la sección de Requisitos de Hyper-V indica:

`Hyper-V Requirements: A hypervisor has been detected. Features required for Hyper-V will not be displayed.
`
