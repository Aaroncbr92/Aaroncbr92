### 2.1 Rundown

Ni el enunciado lo traduce ni hay fuente española que lo defina. Lo que sí consta:

- MOS Protocol v4.0, § 2.3 «Profile 2 – Basic Running Order/Content List Workflow»: **«Profile two
  gives a NCS the ability to build dynamic Running Order/Content List sequences of Item References
  within a Media Object Server.»** y, en «General Work Flow for Profile 2»: **«NCS Stories containing
  Item References can be placed into Running Orders (RO's are also referred to as Content Lists).»**;
  **«The NCS examines all Stories in a RO/Content List, extracts the Item References and uses these to
  build Playlists or Content Sequences within the parent Media Server machine.»**; **«In practice, this
  means that a Story which contains Item References for a Video Object, a CG Object and a Still Store
  Object will create three different playlists – one in the Video Server, one in the CG Server and one
  in the Still Store Server.»**
- La misma norma usa *rundown* y *running order* como sinónimos en su ejemplo: **«Insert example 1 -
  inserting a story in a rundown: Insert a new story with storyID=17 before the story with storyID = 2
  in the 5PM running order.»** (v4.0, línea 4057 del volcado; idéntico en v2.8.5). Y el ejemplo de
  mensaje lleva **«<roSlug>5PM RUNDOWN</roSlug>»**.
- Jerarquía del *running order* (MOS v2.8.5, apartado «Running Orders»): **«1) Running Order (Unique
  ID - may appear only once in the NCS and MOS) 2) Story (Unique ID - may appear only once in the RO)
  3) Item (Unique ID - may appear only once in a story) 4) Object (Unique ID - may appear only once in
  an item)»**; **«Items are sent in the intended order they will be played.»**; **«Multiple Running
  Orders may contain the same Story.»**
- Versiones vigentes (página «Current Versions» del proyecto MOS): **«MOS Version 4.0 was published on
  June 7th, 2019.»**; **«MOS Version 2.8.5 was published on September 7, 2017.»**
- Fabricante (Avid, MediaCentral | Newsroom Management, iNEWS): se define como **«the newsroom computer
  system (NRCS)»**; **«Build rundowns, adjust timing, go live and make real-time changes—even on-air—
  with the lightning-fast performance of the modernized iNEWS client .»**; **«Streamline your control
  room operations by integrating your rundown with studio automation, teleprompters, graphics, and
  video playout servers.»**
- Enlace con la cualificación del ayudante: IMS077_3 incluye entre la información utilizada **«playlist
  de videos»** (UC0216_3, p. 6) y, entre los medios, **«software de escaletas digitales»** (UC0217_3,
  p. 9).
- Lectura (no literal, marcar como tal): *rundown* = escaleta del sistema informático de redacción,
  ordenada en noticias/bloques (*stories*) con elementos (*items*: vídeo, rótulo, imagen fija) que
  alimentan las listas de reproducción de cada servidor. La equivalencia «rundown = escaleta» es de
  oficio; ninguna fuente española leída la fija.
- Qué sistema de redacción usa CSRTV: no consta en documento publicado (ya declarado en 33-04).
